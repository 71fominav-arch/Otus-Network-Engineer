### 1. За пример возьмем офис С-Петербург             

![Схема подключения](./Piter.png)           

В офисе С-Петербург есть только один пограничный маршрутизатор R18 отвечающий за подключение к двум ISP R24 и R26.            
Допустим R24 основной провайдер
Тогда на R18 завернем на R24 весь трафик командой                
ip route 0.0.0.0 0.0.0.0 10.0.20.14 1          
Резервный маршрут пропишем в сторону R26
ip route 0.0.0.0 0.0.0.0 10.0.20.34 1

Возьмем вариант два. С применение PBR.            
На R18 пропишем два маршрута с разными метриками.                                
ip route 0.0.0.0 0.0.0.0 10.0.20.14               
ip route 0.0.0.0 0.0.0.0 10.0.20.34 100              
Допустим есть сервис в интернет (8.8.8.8) к которому хотят получить доступ оба наших пользователя 10.128.16.0/24 и 10.128.17.0/24.             
По умолчанию весь трафик пойдет через R24. Напишем PBR исходя из которого сеть 10.128.17.0/24 идет к ресурсу 8.8.8.8 через второго интернет провайдера.           

ip access-list extended PBR_VPC_Google                
 permit ip 10.128.17.0 0.0.0.255 host 8.8.8.8               
!                 
!               
route-map PBR_VPC_GOOGLE permit 20               
 match ip address PBR_VPC_GOOGLE                 
 set ip next-hop 10.0.20.34             
У R18 два интерфейса к домашним сетям E0/1 и E0/0. Вешаем на оба.                   
!               
interface Ethernet0/0         
 ip address 10.0.2.18 255.255.255.252           
 ip policy route-map PBR_VPC_GOOGLE          
!             
interface Ethernet0/1             
 ip address 10.0.2.26 255.255.255.252            
 ip policy route-map PBR_VPC_GOOGLE            
!              
После таких настроек трафик от VPC к 8.8.8.8 пойдет через 10.0.20.34.
